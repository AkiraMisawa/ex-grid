# ページングは Range Request の駆動源が変わるだけ。アーキテクチャは変えない

ページャ（`1 2 3 … 次へ`）による表示を任意機能として持つ。**押す形のまま、スクロールと
同じ仕組みに乗る。**

```
スクロール : 可視範囲が動いた       → 「500〜560 行目が要る」と鳴らす
ページング : ページボタンが押された → 「500〜550 行目が要る」と鳴らす
```

グリッドから見れば同じで、Consumer 側も `OFFSET / LIMIT` になるだけ。**スクロールと排他では
ない** — 1 ページが縦に長ければページ内でスクロールする。Consumer が `PageSize` を渡すか
どうかの違いしかない。

既存の決定への影響は無い（[ADR-0013](./0013-fixed-row-height.md) の総行数×行高による
スクロールバー計算が不要になる程度）。

## ページングは未解決だった最悪ケースを消す

[ADR-0004](./0004-cap-the-cells-touched-per-frame.md) で「**フリック時の 2000 セルは、どの
描画方式でも予算超過**（実機 25〜33ms）」となり、横仮想化と高速スクロール中の間引きで
対処するとした。**ページャにはフリックが無い。**

```
スクロール : 毎フレーム全セル再構築が連続する → 25〜33ms が続く = もっさり
ページング : ページを押した瞬間に 1 回だけ    → 25〜33ms が 1 回 = 気づかない
```

連続するから体感になるのであって、離散的な 1 回なら知覚されない。**ページングを選んだ画面
では横仮想化を後回しにできる。**

## Ctrl+A はページ内。全行選択は明示的に提示する

[ADR-0011](./0011-selection-is-rectangles-in-index-space-and-is-dropped-on-reorder.md) では
Ctrl+A =フィルタ後の全行と決めたが、ページャがあると文脈が変わる。ページャは「いまはこの
50 行の世界」という印象を強く与えるため、Ctrl+A が 10,000 行を選ぶのは驚きが大きい。

**まずページ内を選び、そのうえで「全 N 行を選択」を提示する**（Gmail 方式）。提示の置き場所は
[ADR-0014](./0014-paste-shape-rules-and-selection-count.md) で入れた選択数の表示。

```
50 個のセルが選択されています  [ 全 10,000 行を選択 ]
```

規則は 1 つに保たれる — **Ctrl+A は「いま見えている文脈」を選び、それを超えるときは明示的に
要求する。** スクロールでは可視範囲が結果全体の連続体なので Ctrl+A が全行、ページングでは
文脈がページなのでページ内。

却下した案:
- **常に全行**（ADR-0011 のまま） — 一貫はするが、ページャの文脈と食い違い驚きが大きい。
- **常にページ内で、全行選択は別操作** — 同じ Ctrl+A がモードによって違う意味になる。
  ADR-0011 で飛び地の「行単位だけ許す」案を却下したのと同じ理由（規則をユーザに説明できない）。

## キーボードはページをまたぐ。ドラッグは境界で止まる

**Shift+矢印 / Shift+Ctrl+矢印はページをめくり、選択が継続する。**
[ADR-0012](./0012-anchor-focus-and-keyboard-navigation.md) の「Focus は常に見えていなければ
ならない」がページングでは「ページをめくる」になるだけ。Enter / Tab の巡回も同様。

これは上の Ctrl+A の決定と矛盾しない。**1 回の操作で見えている文脈を黙って飛び越えないのが
原則**であり、Shift+矢印は 1 行ずつの意図的な拡張なので原則に反しない。

**ドラッグはページの境界で止まる。**

```
スクロール : 下端を越える → 自動スクロール。連続的で、行き過ぎたら戻せば戻る
ページング : 下端を越える → めくる？ 不連続で、カーソルの下の内容が丸ごと入れ替わる
             戻そうとすると前ページへ跳ね返り、行き来してしまう
```

連続的なジェスチャに不連続な遷移を混ぜると狙って止められない。ページャのある UI で
ドラッグがページをめくる例もほとんどない。**ページをまたぐ長い選択は、めくってから
Shift+クリック**が正確で、ファイル一覧などで人が普通にやる操作でもある。

ページ自体が縦に長くてページ内でスクロールする場合、**ページ内では通常どおり自動スクロール
する**。止まるのはページの境界だけ。

## ページをめくっても選択は留まる。画面外にあることを表示する

選択は結果全体に対する通し番号の矩形なので（ADR-0011）、ページをめくっても動かない。変わる
のは何が表示されているかだけ。**留まらないと「めくってから Shift+クリック」が成立しない。**

危険は、選択が見えない状態で貼り付けられること。

```
1. ページ 1 で 50 行を選択  2. ページ 3 へめくる
3. 画面上、選択は何も見えない  4. 値を貼る
5. → ページ 1 の見えない 50 行が書き換わる
```

ADR-0014 の選択数の表示に**一言足して塞ぐ**。判定は選択矩形と表示範囲が交差しているかどうか
だけで、**データは要らない**。

```
選択が画面内     50 個のセルが選択されています
選択が画面外     50 個のセルが選択されています（表示範囲の外）  [ 選択位置へ移動 ]
```

**これはスクロールでも同じように効く** — 遠くまでスクロールしたときにも出る。ページング固有の
対処ではなく、元々あった穴を塞ぐことになる。

## Consequences

- **`PageSize` が渡されればページャ表示、渡されなければ連続スクロール。** グリッドの内部は
  どちらも同じ Range Request で駆動される。
- **`TotalCount` がページャの表示（`3 / 200`）に使われる。** 押す形では既に渡している。
- **「全 N 行を選択」の提示は Chrome の一部になりうる。** 数えるのは核、表示するのは Chrome
  （[ADR-0010](./0010-chrome-seams-column-menu-editor-loading.md) の規則どおり）。
- **選択が画面外にあることの表示は、スクロール時にも出す。** ページング専用にしない。
