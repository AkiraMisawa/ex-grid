`INDIRECT` now reads R1C1 text (`a1` FALSE) that counts from the Formula's own cell or names whole rows or columns, where it gave `#VALUE!`. Excel was observed to read R and C each with a number (`R3C2`, `R03C2`), an offset in brackets (`R[1]C[-1]`, `R[+1]C[-1]`, `R[0]C[-1]`) or no number, the Formula's own row or column (in C2, `RC[-1]` is B2); a row part alone as a whole row and a column part alone as a whole column (`R3`, `C[-1]`); two parts of the same kind joined as the rectangle they span (`R2:R3`, `RC[-1]:R[1]C[-1]`); one cell followed by `#` as its Spill Range (`R1C1#`); a Linked Table's column as text (`Positions[PV]`); and parts of two kinds joined (`R2C2:R3`, `R3:C2`) as no place, `#REF!`. R1C1 text naming another Sheet is `#REF!` whatever follows the name, as A1 text naming one is. Other combinations of these forms are read by the same rule until Excel has been asked them. Still `#VALUE!` until Excel has told what they name: an offset past the Sheet's edge (`R[-5]C[-1]` from row 2, which Excel reads as a place, though not yet which); a row or column number 0 (`R0C2`) or past the Sheet's edge (`R1048577C2`, `R2C16385`), while A1 text past the edge, `XFE1`, stays `#REF!`, as in Excel; and `#` after a range, a row or a column, whatever the parts joined (`R2C2:R3C2#`, `R3#`, `C2#`, `R2C2:R3#`). The same `#` in A1 style (`A1:A2#`, `A:A#`, `1:1#`) is `#VALUE!` too, where it was `#REF!`: it could name no place, the first cell's Spill Range, the cells themselves or the first cell joined to the second's Spill Range, and Excel has not yet been asked which.
