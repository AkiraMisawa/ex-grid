Product: ExGrid
Kind: Behaviour
ADR: 0410

A Chrome's Razor parts stand inside the grid the browser draws: `ExGrid.Components.ExGrid` renders each beside the grid and the grid's script moves it into place and wires its controls there (ADR-0410). `MudGridChrome` draws the column menu, the filter panel, the find panel, the Context Menu and the loading bar this way; its filter panel's operators are native selects and a condition's value is typed as text for every type, so no choice reaches the grid after the Enter that applies it. A Chrome of your own names its parts in the new `IGridChrome.ScriptSlots` and answers each through the overload that takes a view (`ColumnMenu(GridMenuView)`, `ContextMenu(GridMenuView)`, `FilterPanel(GridFilterView)`, `FindPanel(GridFindView)`, `LoadingIndicator(GridLoadingView)`), marking its controls with `ScriptSlotAttributes`. Space, Delete and Backspace on a checkbox or radio button in such a part do what the browser's own control does, whatever the component library's handler would, so a box never shows a tick the grid has not heard. The element a part is drawn in draws no box of its own (`display: contents`), so a part lays itself out in its place as a React Chrome's does; a part that fills the height it is given, such as a Details dialog's records, fills it.
