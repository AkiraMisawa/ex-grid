Product: ExSheet
Kind: Breaking
ADR: 0370

The Razor component drawn in .NET, `ExSheet.Components.ExSheet`, is removed: `ExSheet.Script.ExSheet` takes the same document, Workbook, toolbar and commands, so a page changes `@using ExSheet.Components` to `@using ExSheet.Script` (`ExSheetStylesheet` stays where it was). Its reads cross to the browser, so `ToDocument`, `CellFormatAt` and `LinkedTables` are `ToDocumentAsync`, `CellFormatAtAsync` and `LinkedTablesAsync`. `DefaultRowHeightPx` is now `ExSheet.Script.ExSheet.DefaultRowHeightPx`. `ISheetChrome` keeps the Script Core's slots (`SheetScriptSlots`, `ToolbarItem(SheetToolbarItemView)`, `FormatCells(SheetFormatCellsView)`, `SheetTab`, `SheetTabAdd`); the context overloads and their types (`ToolbarItemContext`, `ToolbarItemFace`, `ToolbarChoice`, `SheetToolbarContext`, `FormatCellsContext`, `SheetFindContext` and the Sheet Tab menu's) are removed, as are `FontToggleItem`, `ColourItem`, `AlignmentItem`, `ToolbarButton.GivesKeyboardBack` and `ToolbarItemKind.Separator`. A Toolbar Item now only declares where it stands, and `ToolbarItemBase` cannot be derived: a button of your own is a `ToolbarButton`. A `PointingScope` refuses a Razor `ExGrid` by name: give the grid `ExGrid.Script.ExGrid`. In ExSheet.MudBlazor, the Razor component's Format Cells dialog, toolbar items, find panel and tab menu are removed; `MudSheetChrome` draws the toolbar, the Sheet Tabs and Format Cells over the Script Core, and needs no `MudDialogProvider`. ExSheet over the Script Core now places ExSheet's stylesheet notice when the stylesheet is missing or stale (ERR-11), as the Razor component did.
