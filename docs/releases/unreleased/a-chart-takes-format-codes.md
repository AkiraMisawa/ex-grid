`ChartAxis.FormatCode` and `ChartSeries.FormatCode` take an Excel number format code in the invariant spelling (`#,##0.00`, `0.0%`, `0.00"x"`, `yyyy-mm-dd`, `mmm yy`), read by the same reader in C# and in the Script Core, and write every value the chart shows: an axis' ticks, the position under the pointer and a range's ends, a series' values in the tooltip and the summary, a candle's change and a merged candle's volume; View as table and the CSV keep values as data. On a Dates axis the ticks step no finer than the code tells dates apart, and a code that tells none apart is refused. Both `ExChart.Components.ExChart` and `ExChart.Script.ExChart` honour it; on the Script one it replaces an axis `Format` and a `Format` on candles, which it refuses. A code the reader does not take, a code of the other kind for the axis or the values, a code on a Categories axis, and a code beside a `Format` are refused by name as the definition is checked. React's `ChartAxisOptions` and `ChartSeriesOptions` gain `formatCode`. The reader moves to `ExGrid.Data` as the public `FormatCode`, and `ExChart.Engine` now depends on `ExGrid.Data`; its refusals no longer speak of a grid ("which the reader does not take").
