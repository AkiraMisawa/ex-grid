`@ex-grid/core` and `@ex-grid/react`, new npm packages, are ExGrid in TypeScript and its React component: the same grid the Blazor component draws, held to the C# core by the cases under `tests/cases/` and by ExGrid's Playwright specs run on a React host. The grid so far takes the Selection, the Cell Editor with IME composition, copy, paste and clear, the Overwrite Notice, the hover and Focus bands (`highlightHoverRow`, `highlightFocusRow`), and the header's drags: a resize from a column's grip or Size to fit by double-clicking it (`onColumnWidthChanged`), and a reorder of a column or a Header Group (`onColumnOrderChanged`), under which a press on a header grabs the column rather than selecting it. A column's width is declared as a number, `{ px, minPx, maxPx }` or `{ auto: true, minPx, maxPx }`. A secondary click, the ContextMenu key or Shift+F10 opens the Context Menu over the Selection: Copy and Copy with headers, then the Consumer's own commands (`contextCommands`), worded by `commandLabel` where the Consumer gives words and in English otherwise, with Copy with headers left off by `hideCopyWithHeaders`. Each header carries a ▾, and Alt+↓ on the Focus opens the same column menu: Sort ascending and descending and Clear filter, which Excel's letters S, O and C run, then Hide, Pin, Unpin and Size to fit, each enabled where the grid hears it (`onColumnHidden`, `onPinnedCountChanged`, `onColumnWidthChanged`); `hideColumnMenu` leaves the ▾ off. Below the commands stands the column's filter panel: a value list with a search, "(Select All)" and the Blank entry where the column declares `filterUi: 'valueList'` or `'both'`, and the condition form, one or two conditions joined by And or Or, where it declares nothing or the source answers TooMany. A typed value is read in the grid's `locale`, a BCP 47 tag or `'invariant'` (the React component passes the browser's language when given none), and refused by name where it does not read; a date is made with the `temporal` option, the browser's Temporal or a polyfill's, which a grid with a filterable Date column is refused without, on every browser alike. Ctrl+F opens the find panel in the grid's top right where the source finds, as `GridSource.from`'s does: Enter and Shift+Enter step through every row, painted or not, the column headers and Header Group labels first in the walk (off with `findsHeaders: false`), and every painted match wears the Match Mark, by the reference rule over an in-memory source and by `findMatch` over any other. Ctrl+H adds Replace where `onReplace` is given and a column is editable: Replace writes the current match through `onEdit`, and Replace All is one request the Consumer answers, which `GridSource.from`'s `replace` performs. A Find or Replace that moved or wrote nothing reaches `onRefused` with the kind `find`, and the panel says why. An Action Column, made by `actionColumn`, paints the grid's own buttons and reports a press through `onAction` on the row it was pressed on as the Window holds it now, or refuses it through `onRefused` with the kind `action` where that row is gone, the order moved or the source was replaced. Space fires a cell's one action; on a cell with several it enters it, ← and → choose, Space fires the chosen one and Escape leaves, and Enter and Tab never fire. A column's `template` mounts the Consumer's content into its cell and is told when to take it away; `templateColumn` in `@ex-grid/react` renders React content there, and Space hands the content a request to take the keyboard. A Mark Column, made by `markColumn`, paints a checkbox on every row and one in its header, over the Row Marks a `GridSource.from` source keeps or the `marks` option holds: a checkbox marks its row by identity, the header marks or unmarks the whole result, Space in the column brings the selected rows into line, and the count below the grid says how many are marked and how many lie outside the current filter. A press the order or a replaced source has overtaken marks nothing and reaches `onRefused` with the kind `mark`. `GridSource.fetch` keeps Row Marks given a `marks` adapter, a `RowMarkAdapter`: a row's key, the server's marker for the result at a header press, whether a row belonged to it, and the server's counts. The marks are kept as keys and snapshots, never positions (`marks.state`, a `RowMarkState` the server counts and acts on), the counts are asked for again whenever the Filter, the marks or the size of the result move and `marks.recount()` is there for news only the server has, and a failure met while marking reaches `onFetchFailed` as a failed fetch does. Selecting two cells or more shows Excel's status-bar figures below the grid, the Selection Summary: Average, Count and Sum unless `summaryFigures` names others, answered by a source that summarises, as `GridSource.from`'s does, or by `onSummarize`, which may decline with a reason (`declinedSummary`). The line says Calculating… while a question is out and shows only the answer to the current selection; it stands whenever the grid can summarise, so a grid over `rows` now has it, and `showSelectionSummary: false` leaves it off while `onSelectionSummaryChanged` still hears every change. The figures take the Focus column's format, and the grid's handle, and the React component's ref, offer `refreshSummary()` for values that moved where the grid cannot see. Every Row Sequence Version the grid hands a Consumer, in an intent, the Context Menu's context, `readView` and the viewport's `data-ex-sequence`, is its source's own, the one `snapshot()` says and `placeSelection` and `showViewWith` take; rows handed as a new array are a source of their own, which counts from 0. They are published with 0.3.0.
